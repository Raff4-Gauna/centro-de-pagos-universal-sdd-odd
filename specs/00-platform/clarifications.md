## I. Casos límite — SPEC-00 (checklist de la plantilla)
- [x] **Concurrencia:** dos PR que agregan migraciones a la misma app → dos hojas en el grafo; `makemigrations --check` / `migrate` fallan en CI y se resuelve rebaseando y renumerando (o migración de merge sin operaciones, que es reversible). Dos PR que cambian el contrato → conflicto en `openapi.yaml`, se resuelve regenerando. `migrate` no corre en el entrypoint de `worker`/`beat` (si arrancan a la vez compiten por el lock de la tabla): un solo comando o servicio lo ejecuta (detalle en design). Una sola réplica de `beat`.
- [x] **Reintentos y repetición:** re-ejecutar un job de CI es idempotente (cada job crea su BD descartable). Pre-commit que reformatea aborta el commit la primera vez y hay que volver a stagear (se documenta). La tarea de diagnóstico no tiene efectos de negocio. Push nuevo después del veredicto del `reviewer` → el veredicto ya no cita el último SHA y el check de zona roja vuelve a fallar (Q-042).
- [x] **Orden:** arranque de Compose ordenado por `depends_on: condition: service_healthy`; si Redis o la BD tardan, el worker reintenta la conexión con backoff y logueando cada intento (sin bucle silencioso). Sin eventos de negocio en 00.
- [x] **Fallas parciales:** una imagen buildea y la otra no → paso 9 rojo, no hay build "a medias" que valga. `docker compose up --wait` termina con error si un servicio no queda `healthy`, y nombra el servicio. El script de verificación de protección, si la API de GitHub falla o responde algo inesperado, termina en error ("no verificado"), nunca en éxito.
- [x] **Proveedor caído / lento / 429:** no hay proveedores de pago en 00. Dependencias externas de CI: GitHub Actions caído → no se puede mergear (aceptado: sin bypass); PyPI, npm o Docker Hub caídos o con límite de descargas → el job falla y se reintenta; mitigación con caché de dependencias e imágenes base por tag/digest. Límite de la API de GitHub para el script → corre con el `GITHUB_TOKEN` del workflow.
- [x] **Permisos:** sin roles de negocio en 00 (§H). Repo público: cualquiera puede forkear, abrir PR y comentar, pero no puede mergear, poner labels ni hacer que su comentario cuente como veredicto. El dueño no tiene bypass.
- [x] **Aislamiento:** no aplica a datos (00 no tiene tablas de negocio); el test de arquitectura C-01 queda activo desde el primer commit (AC-PLT-15).
- [x] **Estados terminales:** no aplica (no hay máquinas de estado en 00).
- [x] **Montos:** no aplica, salvo el chequeo de C-02 (RN-PLT-20, AC-PLT-31).
- [x] **Vencimientos:** una excepción de auditoría de dependencias vencida vuelve a hacer fallar el paso (Q-037, a propósito). No hay vencimientos de negocio.
- [x] **Desactivación/borrado:** no aplica. Volúmenes nombrados: borrarlos es la forma documentada de recrear la BD (toda BD es descartable hasta 01, Q-053).
- [x] **Zona horaria:** BD en UTC (`USE_TZ=True`), presentación `America/Argentina/Buenos_Aires` (Q-046); `timestamp` de los logs en ISO-8601 UTC; los runners de CI están en UTC y la TZ del host Windows no importa porque todo corre en contenedores; un test que dependa de la hora usa un reloj fijo.
- [x] **Volumen:** los healthchecks de Compose consultan cada pocos segundos: sus requests no deberían loguearse a nivel INFO (detalle en design) para no tapar los logs útiles. Logs sin cuerpos (RN-PLT-06) mantienen acotado el tamaño por línea.
- [x] **Datos vacíos / inválidos / muy largos / caracteres especiales:** `X-Request-ID` enorme, con saltos de línea o que no es UUID → se reemplaza (AC-PLT-09); variable de entorno vacía o con formato inválido → no arranca, nombrando la variable (AC-PLT-03); ruta del repo con caracteres no ASCII (`Programación-2026`) → los scripts no asumen ASCII en rutas; CRLF → LF (AC-PLT-27).
- [x] **Privacidad:** los logs no llevan PII ni secretos (RN-PLT-06); repo público → nada sensible entra nunca (RN-PLT-18) y el contenido ya commiteado se revisa antes de publicar (Q-054).
- [x] **Observabilidad:** CI rojo visible en el PR; `/readyz` 503 cuando falta BD o Redis; el worker con fallas repetidas queda `unhealthy` en Compose (healthcheck propio, p. ej. ping de Celery) en lugar de reiniciarse en bucle sin dejar rastro; cada request y tarea con `duration_ms` (RNF-PLT-03).
